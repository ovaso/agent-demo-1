## 设计到实现的主线

1. **建立统一执行框架。** 将规划、路由与协作职责分开，由 Runtime 校验并提交状态变化，管理预算、检查点与恢复；模型输出的计划或完成说明需要经过运行时接纳。
2. **协调 Loop 与 Graph。** Loop 用于逐轮推进，Graph 用于有依赖的工作项执行；计划提交、执行路由和节点结算分别处理，模式切换保留任务状态与已用预算。
3. **扩展多 Agent 协作。** 在独立上下文、委托与结果接纳的基础上，提供共享记录、消息、请求、答复和等待机制，明确版本、权限与恢复边界。
4. **明确当前落地范围。** 当前为共享 Provider、同步顺序调度的平面团队；有界并行、不同 Provider 的角色池和更深委托仍属于后续能力。多 Agent 不等同于已实现并行执行。
5. **提供操作入口。** 通过 CLI 查看计划与状态、切换路由、恢复任务、操作委托和协作消息。详细命令以第 03 篇为准。

上述是现有材料的概念演进整理，不补写未经记录的实现时间线；具体提交、历史验证和限制保留在各文档中。
