# 有界预算续期

[文档总索引](../README.md)

测试数量与体积属于删除测试之前的历史功能阶段，不代表当前回归结果。当前验证要求见[项目约定](../../AGENTS.md#验证与交付)，执行结果见[实现状态](../runtime/02-implementation-progress.md#当前验证证据)。

运行时区分当前已获准的累计模型额度与自动执行的总硬上限。达到当前额度后，根据已经接纳的近期工作结果决定是否续期；续期有单次增量、次数和总硬上限三重约束，所有消耗仍属于原任务。

## 核心策略

`RunLimits.max_steps` 表示当前已获准额度，`step_extension` 可选策略包含 `hard_max_steps`、`step_increment` 与 `max_extensions`。核心库的 `RunLimits::new(n)` 继续使用固定额度，调用者显式设置策略后才启用自动续期。应用新任务默认采用初始 8 步、硬上限 32、单次最多 8 步、最多 3 次；环境配置见 [CLI 说明](../runtime/03-runtime-cli.md)。

续期不额外调用模型。运行时只在准备下一次模型请求且当前额度用尽时评估；满足以下条件才授予 `min(当前额度 + 单次增量, 硬上限)`：

- 尚未达到硬上限，且续期次数未耗尽（策略最多允许 16 次）。
- 自上次续期后观察到新的成功工作结果。
- 最新进展位于最近两次模型调用内，避免用很久以前的结果反复续期。

进展包括成功的业务工具结果、接纳的计划/委托/协作答复，以及成功结束的图节点。工具失败、权限拒绝、状态和收件箱轮询不计入。工具观察对工具名、参数和结果做固定指纹去重，保留最近 64 个指纹；已消耗的进度序号不能再次换取额度。指纹用于有界的近期新颖性判断，不是密码学验证，也不能证明任务已实际完成；包含变化时间戳的重复结果等情况仍可能被视为新结果，总硬上限和次数约束始终生效。

计划、委托和答复在实际接纳状态变更的位置记录进展，模型工具和操作者 API 使用同一判定。人工答复保持暂停状态，但可以为后续恢复提供新进展；相同答复的幂等重投不会重复计入。仅记录这些受校验的控制变更，普通状态读取不获得续期。

## 恢复与边界

每次授予额度先保存检查点，再允许下一次模型调用。记录授予时已用步数、前后额度和本次新进展数量，并输出 `runtime.budget.extended` 轨迹事件。重启、模式切换或暂停不会重置根用量、续期次数或去重记录。

工具次数、状态转换次数、检查点容量、只规划权限与子 Agent 局部额度不自动扩大。未知工具副作用仍先进入核实流程。达到硬上限或没有足够进展时保留检查点并暂停，不通过额外的“判断模型调用”越过硬上限。

旧检查点缺少策略时继续固定额度。操作者可调用 `Runtime::set_step_extension_policy` 启用续期；首次接纳旧记录时，只能从安全边界上的最后一条已确认成功的工具结果建立进度，不能将任意历史文字当作进展。该操作保留暂停状态与已用量。

`Runtime::set_max_steps` 明确设置一个固定的累计额度并关闭自动续期，保留历史。重新启用策略不会返还已使用的续期次数；操作者修改策略属于新的明确授权，模型没有更改这些上限的控制入口。

## 应用体验

预算配置可以写入 `.env`，启动时按进程环境优先的规则加载；文件选择和模型/路径配置同样适用，详见 [启动环境配置](../common/environment.md)。

`/budget auto <硬上限> [运行 ID]` 为已有任务启用策略，保留暂停状态并通过 `/resume` 继续。单次增量和次数采用当前应用的续期配置；应用关闭默认续期时，该命令显式启用默认的 8 步/3 次策略。`/budget <固定总额度>` 关闭自动续期；`/budget` 查看状态。

模型上下文提供已获准额度、剩余硬额度、剩余续期次数及当前阻止续期的原因，提示模型接近上限时收敛结果并说明未完成事项。CLI 展示额度策略和每次续期记录，达到预算时说明暂停原因与恢复方法。系统在硬上限后不再调用模型生成“收尾说明”，因此上限仍有效；保存的状态和工具结果可以继续恢复。
