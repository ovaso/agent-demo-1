# 可恢复任务 CLI

普通文本会建立一个新的运行任务并执行，终端显示运行 ID。默认仍为最多 8 次模型请求；通过 `RS_AGENT_MAX_STEPS` 设置新任务总额度。网络失败后的重试也计入原任务预算。

数据库默认复用 `agent-context.sqlite3`，可通过 `RS_AGENT_DB` 指定；旧会话记录继续可用。`RS_AGENT_MEMORY_DIR` 默认为 `memories`。数据库新增运行表及执行锁文件，保留 SQLite bundled 部署方式。

## 逐步查看执行

```text
/start 请调查这个问题
/step
/status
/step
/pause
/resume
```

`/start` 只建立任务检查点。每次 `/step` 推进一次模型调用、一个工具或收尾阶段，工具实际执行前后均保存进度。`/pause` 后普通 `/step` 保持暂停，需要明确 `/resume`。

## 重启恢复

重新运行应用时会提示当前会话未结束的任务。执行 `/resume` 使用保存的输入、工具队列和已消耗额度；不会追加同一用户输入。可用 `/resume <运行 ID>` 指定任务。

不调用模型也能在命令行查看状态，无需模型 API 环境变量：

```sh
cargo run -p agent-app -- --status
cargo run -p agent-app -- --status <运行ID>
```

额度耗尽后，如需继续，可显式调整总额度再恢复：

```text
/budget 20
/resume
```

这里的 20 是新的总额度，包含此前已经消耗的调用。`/cancel` 终止任务并保留历史；未结束任务不能被新的普通输入覆盖。`/reset` 仅清理已结束任务的当前会话历史，不删除检查点。

## 工具结果未知

如果工具开始执行后进程退出，恢复会停止在结果待核实状态。先检查外部状态，再选择：

```text
/resolve <工具调用ID> <已核实的结果>
/resume
```

只有确认工具尚未执行或可安全重复执行时，使用显式重试：

```text
/retry <工具调用ID>
/resume
```

这两个命令默认操作当前会话最新任务，调用 ID 必须匹配其待核实工具。`/resolve` 保存普通工具结果；会话结束工具若中断，可在确认其安全性后使用显式重试。模型不能自行调用这两个恢复控制入口。

暂停和取消在安全边界生效。目前 CLI 不承诺在同步模型请求或工具执行中立即中断；Ctrl+C 取消的是终端输入。进程被终止后的未决副作用仍需核实。

## 当前实现边界

现阶段提供可恢复的单 Agent Loop、模型规划与 Blackboard。Graph、路由和多 Agent 协作按实现记录继续扩展。

运行存储以完整、有大小上限的检查点保存。一个数据库同时允许一个执行者，其他连接可以读取已提交状态；任务内并发尚未启用。恢复要求模型标识和已授权工具定义与检查点一致。新注册工具不会自动授予旧任务。追踪中每次执行段拥有独立调用树，`logical_run_id` 将恢复段关联到同一任务。

## 规划与共享记录

```text
/plan 调查问题并给出修改与验证计划
/plan
/board
/execute
```

`/plan <任务>` 允许调用 `read_file`、`list_directory` 和 `search_files` 等明确只读的能力，以及运行时计划和 Blackboard 工具；通用 `run_cmd` 与写文件能力被运行时禁止。`search_files` 需要 PATH 中存在 rg，固定其参数并禁用用户配置。

模型通过 `runtime_plan` 提交包含依赖与验收条件的结构化计划，通过 `runtime_board_write/read` 保存和读取共享记录。模型的共享记录作者由运行时填写，不能自行写入程序验证类型。数据量、计划版本数与修订数有明确上限。

计划交付后任务保持 `PlanReady`，`/resume` 不会进入执行；`/execute` 明确转换工作意图并使用原任务额度继续。需要时先用 `/budget` 调整总额度。普通任务也可按需使用规划工具，不强制增加单独的规划模型调用。

`/plan` 不带任务文本时展示当前计划，`/board [key]` 查看共享记录。目前 `/execute` 由 Loop 按计划推进，提交的图依赖还不承担实际调度。
