# 缓存与输入预算

缓存命中以服务商 usage 为准。OpenAI 兼容适配器同时支持
`prompt_tokens_details.cached_tokens` 和 DeepSeek `prompt_cache_hit_tokens`；
前者存在且为零时不会被后者覆盖。未知报告保留为 unknown。

trace-map 的 `cache_tokens` 是缓存读取 Token / 全部输入 Token。
`hits/reports` 是有命中的请求数 / 上报缓存的请求数，两者口径不同。
总输入已包含缓存输入，输出已包含思考 Token，不能再重复相加。
汇总中有缺失报告时不生成看似完整的 Token 命中率；可用 reports 与 calls 检查覆盖。

模型的长度截断、拒绝和其他未完成结束原因不代表任务完成。
运行时保留已输出的文本并暂停，`/resume` 在原预算内继续；该轮的工具调用不会执行。
OpenAI 与 Anthropic 的完整响应、流式响应均转换为统一的停止原因。

DeepSeek/OpenAI 的 reasoning_content 与 Anthropic 的有序签名思考内容会随
assistant 消息保存，跨进程 resume 后按原协议回传。续接数据绑定协议、主机和
请求模型，不保存 URL 凭据或查询参数；改变绑定时需要新的会话。
trace 的 response_model 记录服务商返回的模型名，原有 model 记录请求配置。
Provider 的流式与完整响应均限制为最多 8 MiB，超限或中断不会执行部分工具。

执行状态不再重复传递已在 tools 中声明的 schema。PlanOnly 协调者仅保留
尚未开放执行的工具目录；子 Agent 仍由其工具权限限制能力。
节点结果默认只携带至多 512 字节的 UTF-8 预览，output_truncated 标记截断，
需要完整证据时使用 runtime_result 分页读取。

运行状态以完整快照开始，后续按字段追加状态增量并保存到检查点，既有历史不重写。
协作输入与投递标记在发请求前一起持久化，模型失败或进程恢复不会丢失准备好的输入。
每个 actor 独立保留最近状态；历史裁剪/清空后补充完整快照。旧检查点缺少此元数据时
自动建立第一个快照，已用预算不重置。runtime.prompt.updated 记录角色、更新字段、
快照类型和历史代数，不记录消息正文。

长期记忆按数量、单条与总字节数选取；Markdown 读取每个文件时即限制字节，
SQLite 在解码正文前过滤超限记录，选取按 ID 稳定排序。自定义 MemoryStore 可覆盖
search_bounded 以约束自身 I/O；默认实现只限制返回结果。被略过的文件或匹配项会
标记 truncated，不伪装为完整检索。记忆来源路径可用于按需读取。

运行时把选中记忆作为尾部数据保存，不再每次替换首部 System；跨问题更新也只追加。
子 Agent 接收来源与短预览，可按工具权限读取详情或向协调者请求。恢复旧检查点时
同样应用上限。完整 Provider JSON 请求通过有界编码器校验，包含全部工具、记忆、
会话和协议字段，并复用该编码缓冲区发送 HTTP。

输入诊断记录 system/history/memories/tools 的逻辑 JSON 大小与非安全用途的指纹；
只有同程序版本内的比较有意义，不代表服务端 tokenizer 或缓存键。
request_bytes 是实际发送的 JSON 正文字节。运行时记忆已包含在 history 中，
不能再把 memories 目录大小或 checkpoint 大小当作模型输入量。

应用默认在模型调用边界按高低水位批量压缩上下文，工具批次进行中不裁剪。
用户指令与协作消息原文保留；旧 assistant/tool 内容转为有界的原文摘录，
重建型运行状态与记忆数据可省略并在下一请求重建。该过程不额外调用模型，
摘录明确标记不完整，不能当作新指令或完整验证证据。

普通近期工具批次保持完整；单个完整批次本身超过高水位时也可整体归档，
不会留下孤立工具结果。用户指令过大时不截断指令，硬请求上限仍会阻止超限发送。
低水位是压缩目标，保留原文和完整批次可能使结果略高于目标。
压缩会产生一次可观测的前缀切换，此后继续追加。runtime.context.compacted
记录前后逻辑大小、归档消息数与历史代数。关闭压缩恢复原数量窗口。

根任务的 Token 账本在发请求前持久化预留，正常响应以服务商 usage 结算；
失败或进程中断保留估算消耗。输入预留采用逻辑 JSON 字节的保守估计，并使用
已观察到的服务端额外输入校准；它不是精确 tokenizer，也不是金额上限。
累计输入已含缓存读取，输出已含思考，均只计一次。主/子 Agent 与 resume 共用账本。

余额不足以发送下一轮时 Paused(TokenBudget)，不会丢失检查点；单次输出额度可
随剩余预算降低。服务商实际报告高于估计时如实记录，之后不再超预算发新请求。
未知输出且未设置输出边界、或旧检查点缺少历史账本时，标记“历史未计量”，
不能据此启用可靠的完整累计上限。新任务默认启用；旧任务仍保留原步骤边界。

模型响应的文本、工具调用和续接数据作为整体检查大小，超限调用不能先执行副作用。
