# 有界预算续期

运行时区分当前已获准的累计模型额度与自动执行的总硬上限。达到当前额度后，根据已经接纳的近期工作结果决定是否续期；续期有单次增量、次数和总硬上限三重约束，所有消耗仍属于原任务。

## 核心策略

`RunLimits.max_steps` 表示当前已获准额度，`step_extension` 可选策略包含 `hard_max_steps`、`step_increment` 与 `max_extensions`。核心库的 `RunLimits::new(n)` 继续使用固定额度，调用者显式设置策略后才启用自动续期。默认策略为硬上限 32、单次最多 8 步、最多 3 次；应用默认入口在后续步骤接入。

续期不额外调用模型。运行时只在准备下一次模型请求且当前额度用尽时评估；满足以下条件才授予 `min(当前额度 + 单次增量, 硬上限)`：

- 尚未达到硬上限，且续期次数未耗尽（策略最多允许 16 次）。
- 自上次续期后观察到新的成功工作结果。
- 最新进展位于最近两次模型调用内，避免用很久以前的结果反复续期。

进展包括成功的业务工具结果、接纳的计划/委托/协作答复，以及成功结束的图节点。工具失败、权限拒绝、状态和收件箱轮询不计入。工具观察对工具名、参数和结果做固定指纹去重，保留最近 64 个指纹；已消耗的进度序号不能再次换取额度。指纹用于有界的近期新颖性判断，不是密码学验证，也不能证明任务已实际完成；包含变化时间戳的重复结果等情况仍可能被视为新结果，总硬上限和次数约束始终生效。

## 恢复与边界

每次授予额度先保存检查点，再允许下一次模型调用。记录授予时已用步数、前后额度和本次新进展数量，并输出 `runtime.budget.extended` 轨迹事件。重启、模式切换或暂停不会重置根用量、续期次数或去重记录。

工具次数、状态转换次数、检查点容量、只规划权限与子 Agent 局部额度不自动扩大。未知工具副作用仍先进入核实流程。达到硬上限或没有足够进展时保留检查点并暂停，不通过额外的“判断模型调用”越过硬上限。

旧检查点缺少策略时继续固定额度。操作者可调用 `Runtime::set_step_extension_policy` 启用续期；首次接纳旧记录时，只能从安全边界上的最后一条已确认成功的工具结果建立进度，不能将任意历史文字当作进展。该操作保留暂停状态与已用量。

`Runtime::set_max_steps` 明确设置一个固定的累计额度并关闭自动续期，保留历史。重新启用策略不会返还已使用的续期次数；操作者修改策略属于新的明确授权，模型没有更改这些上限的控制入口。

## 核心验证

新增 12 项测试，覆盖硬上限和末次增量裁剪、次数限制、新结果与重复/过期结果、失败和轮询、其他资源上限、委托局部额度、Loop/Graph 切换、手动配置后的历史保留、旧检查点接纳、未知副作用、无效策略，以及 SQLite 在已保存续期和请求预留后重启。

格式、Clippy、workspace 202 项测试与核心库无默认 feature 65 项测试通过。相同工具链和 release 命令下，应用为 6,157,344 字节，较本功能前的 6,153,792 字节增加 3,552 字节。核心阶段无新增依赖；尚未测量启用续期后的运行耗时。
