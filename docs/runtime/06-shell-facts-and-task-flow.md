# 06 · 运行事实、Shell 对话与任务执行流程

[阅读索引](README.md) · [统一 Agent 规格](04-unified-agent-spec.md) · [最小启动与结果接纳](05-agent-startup-and-result.md)

日期：2026-09-11。状态：用户已明确下述产品流程；实现尚未完成。本文区分已确认方向与为落实该方向提出的细化建议，本轮仅修改文档。

## 1. 已明确的流程与适用关系

用户明确要求：

1. 应用启动时自动获取可用事实，至少包括环境变量、可用工具/命令行程序、系统版本与发行版、本机 IP；在内存中保留整个运行生命周期。
2. 提供运行期间更新事实的内部函数，不能作为对外能力或模型工具集暴露；具体触发时机暂不确定。
3. 启动后默认进入 Shell 对话模式，可选择 think 及其强度。普通对话只需精选上下文，不要求加载当前系统事实，也不自动进入 Task、Planner、Agent Loop 或多 Agent 流程。
4. 模型判断需要执行任务，或用户手动指定 `/plan`、`/resolver` 时，才进入任务流程。用户已进一步确认：`/resolver` 表示直接执行、按需规划；`/plan` 沿用只调查和交付计划的语义。
5. 任务 Agent 采用统一入口：`agent(context(evidence, memory, tools, config), task_description, planner_enabled, id)`。
6. 每个任务无论是否使用子 Agent，都有公共 Blackboard，同步任务、进度和依赖，并登记不同 Agent 间建立的临时协作 Blackboard。
7. 任务执行期间适时在 Loop 与 Graph 之间切换。

这明确了前两篇设计的上层入口：第 04、05 篇描述的是**进入任务后的 Agent**，不再把应用启动、普通 Shell 对话或每次用户输入等同于创建一个任务。本文的最新明确要求优先；前文的任务预算、验收和恢复规则继续在任务范围内适用。

## 2. 三个生命周期

| 范围 | 创建时机 | 持有内容 | 结束与恢复 |
| --- | --- | --- | --- |
| 应用进程 | 应用启动 | 运行事实内存仓、Provider/连接与基础配置 | 进程退出后释放；重启重新采集事实 |
| Shell 会话 | 进入对话界面 | 会话历史、精选上下文、think 配置、入口判断和会话用量 | 对话可持续，跨任务关联交付摘要；会话恢复策略与任务恢复分开 |
| 根任务及 Agent | 确定进入任务后 | 公共 Blackboard、统一 Agent 输入、计划/依赖、局部上下文、预算与验收 | 完成、暂停、阻塞或取消；按任务检查点恢复 |

主、子 Agent 复用应用事实仓，不在创建每个 Agent 时重复枚举系统。公共 Blackboard 以根任务为范围，不让无关任务共享一套可修改状态。纯对话没有虚构的 task_id、任务验收条件或任务公共板。

## 3. 应用启动时采集事实

### 范围与含义

“所有可用事实”在首版落实为对已定义事实域的完整枚举；当前进程实际能访问的内容才可称为已取得。不可读取、查询失败或达到资源边界时保留明确状态，不伪装成已完整获取。

| 事实域 | 采集内容建议 | 边界 |
| --- | --- | --- |
| 环境变量 | 当前进程可见的环境变量名称及原始值 | 使用可表示本机原始字符串的形式；应用加载的环境文件/有效配置另标来源，不能冒充进程实际环境 |
| 可用命令 | 当前搜索路径中的可执行程序名称、路径及解析优先顺序；相关 shell 信息 | 不通过逐个执行程序来枚举；重复名称保留路径与实际优先项。内建命令、别名与外部程序分开记录，未能发现的内容明确标记 |
| 系统信息 | 系统类型、版本、发行版信息、架构等本机可读取信息 | 各平台使用相应采集实现；不可用字段保持未知，不编造发行版 |
| 本机地址 | 本地网络接口及其 IPv4/IPv6 地址，标注接口和回环等属性 | 本机可能有多个地址，不随意选一个作为唯一 IP；不默认访问公网服务查询出口地址 |

可用命令事实与 Agent 工具授权分开：本机安装了某程序，不表示模型获准执行它。工具 schema、Registry 和授权集合仍由任务配置决定；不把 PATH 清单直接转换成一组模型工具。

采集行为不依赖模型。候选目录数、读取量、结果大小及可能阻塞的本机查询需要有界；具体上限和平台策略在实现前确定。用户要求的事实域必须都有采集结果或明确的不可用/受限状态，不能只采集其中方便获得的部分。

### 内存事实仓

应用持有一个共享事实仓，内容至少包括：进程实例标识、快照修订、各域的观察时间、来源、值和完整性/错误状态。事实值是带时间的观察，不是永远不变的配置或系统指令。

原始事实保存在本进程内存，持续到退出；不把完整环境变量和地址清单自动写入会话、Blackboard、日志或检查点。任务需要时生成相关且允许向模型提供的事实视图，密钥等原始值继续留在内部。采集所有可用环境变量与向模型发送这些变量是两个步骤。

任务确实使用过的事实视图可以作为该次执行证据随任务上下文保存，记录所用的进程实例、修订和观察时间；这不把整个实时事实仓改为持久化仓。恢复时保留历史依据，新进程事实重新采集，二者不能混成同一时间的环境。

### 内部更新功能

提供仅由应用内部调用的刷新函数，逻辑操作为：选择事实域 → 重新采集 → 校验 → 发布新内存快照 → 返回更新结果。实现可使用 `pub(crate)` 等内部可见性，不注册到普通工具、debug 工具、Runtime 模型工具或 slash 命令。

刷新要求：

- 支持更新指定事实域或全部域，并返回更新了哪些域、哪些失败以及新修订。
- 发布后读取者看到一致快照；失败域保留上次成功值及原观察时间，并标明本次失败，不能给旧值套上新的观察时间。
- 刷新事实不自动改写进程环境、Provider 配置、任务授权或系统提示词。
- 已发送请求继续绑定原事实视图；新快照对任务的影响在下一安全边界按相关性选择，不修改正在进行的工具批次。

**已确定自动采集的时机只有应用启动。** 运行期刷新能力必须具备，但暂不指定定时器、每轮刷新、模型触发或进入任务就刷新。任务入口读取当时已有的内存事实快照，不隐式引入新的刷新触发器。

事实采集的个别失败应可见，但与普通对话无关的事实缺失不必阻止 Shell 对话；任务真正需要该事实时再处理缺失。

## 4. 默认 Shell 对话

这里的 Shell 是终端中的对话入口，不表示把自然语言直接交给操作系统 shell 执行。

普通输入首先依据精选会话上下文处理。纯对话请求不附加实时系统事实、任务 Blackboard、业务工具 schema 或任务执行规则，不创建 RunState，不启动持续至任务完成的 Agent Loop。

会话可以有用于对话行为和入口判断的少量协议规则；任务系统提示词在进入任务后才装配。纯对话中存在多个用户来回，不等于后台持续执行任务。历史中用户已提供的事实仍可按相关性选取，但不能因此称为当前实时系统状态。

### Think 与强度

Shell 支持用户选择是否启用 think 及强度，二者属于生成配置，与是否进入 Task 独立。开启 think 的普通对话仍可以是一轮普通回复。

适配器负责将设置映射到具体模型支持的参数；不支持的开关或档位明确反馈，不静默改成其他强度。默认状态可沿用 Provider 默认设置，实际生效值及来源应可查看；最终操作命令/控件名称另行确定。

细化建议：会话设置从下一次会话请求生效，新任务默认继承当次设置并保存到任务配置。已有任务恢复使用已保存设置；若用户要求修改正在进行的任务配置，通过明确的任务配置修订处理。切换时保留模型续接兼容性，不通过清空历史掩盖不兼容，也不每轮重建 HTTP Client。

### 会话用量

纯对话仍受单次输入/输出边界约束并记录服务商用量，但无需创建任务步数账本。Shell 的入口判断与 Task 内的规划/路由区分记录。

细化建议：创建任务之前发生的 Shell 对话/入口判断消耗记在会话，进入任务后的请求计入根任务预算；关联展示入口判断成本，不重复计入两套合计。原任务内的继续、规划、路由和验收不得伪装成新会话请求来绕过任务预算。完整会话累计限额如需新增，另定配置，不凭空引入默认额度。

## 5. 从对话进入任务

| 入口 | 行为 | Planner 关系 |
| --- | --- | --- |
| 普通输入，模型判断可直接回答 | 输出对话回复并留在 Shell | 不创建 planner 或任务 |
| 普通输入，模型判断需要执行任务 | 将用户要求及选中上下文交给任务入口，Runtime 校验后创建或继续任务 | 按任务配置决定是否开放规划；不要求所有任务先规划 |
| `/plan` | 显式进入调查、分解与计划交付 | `planner_enabled=true`，工作意图为只规划 |
| `/resolver` | 显式进入执行，简单工作可直接推进，复杂工作按需规划 | 默认开放规划能力，但不强制首先完成独立规划阶段 |

`/resolver` 是本次确认的新模式名，与现有 `/resolve <工具调用 ID> <结果>` 的未知工具结果核实命令不同，不能作为其缩写或别名。

### 模型判断与切换边界

模型判断的是“如何处理当前用户意图”，不授予新的工具或副作用权限。解释一个命令如何使用可以直接对话；实际读取本机状态、修改文件或执行操作则需要进入任务路径。普通问题不能因开启 think、话题复杂或提及代码就自动变成执行任务。

入口判断建议与本轮会话响应合用一次模型请求，返回可校验的回复/任务分支及任务候选信息。精确线格式和跨 Provider 适配仍需确定，不能以扫描自由文本中是否出现“任务”来触发执行。分支无效或响应中断时不派发业务操作。

流式设计应先确认有界的分支信息，再增量展示回复；不能为了识别分支而收齐整段长回复。进入任务的控制信息与用户可见答案分开，不能将路由协议片段作为回答输出。

任务分支必须绑定来源会话轮次，保留用户原文、相关约束及材料引用。先校验、保存任务入口决定及初始状态，再允许第一个任务模型请求或工具操作；同一轮次恢复/重投不能重复创建任务。

### 已有任务与模式返回

细化建议：任务完成后把交付摘要与来源引用接回 Shell；计划交付、预算暂停或协作阻塞时也允许回到对话入口，但任务状态保持可恢复，不能将返回 Shell 当作任务完成。

有未结束任务时，普通闲聊可以直接回复；与原任务有关的继续或修改绑定原 task_id、预算与 Blackboard，不重新创建一份任务。新独立任务与原任务的并存策略首版沿用单活动任务限制，不能静默取消原任务或借新 ID 重置其额度。模型判断不隐含解除用户主动暂停或 `/plan` 的只规划意图。

`/plan`、`/resolver` 的无参数行为、模式是否只作用于下一次输入，以及与 `/start`、`/execute` 的最终映射需在 CLI 设计中定稿；本文确认两者的业务语义，不把尚未实现的命令写入当前使用说明。

## 6. 进入任务后的统一 Agent 输入

采用用户给定的逻辑入口：

```text
agent(
    context(evidence, memory, tools, config),
    task_description,
    planner_enabled,
    id
)
```

主 Agent、委托子 Agent 和 Graph 中的 Agent 节点使用同一输入语义。下面说明字段职责；最终 Rust 类型和外部工具封装尚待定稿。

| 输入 | 内容与来源 |
| --- | --- |
| context.evidence | 精选会话片段、任务证据、依赖结果、工作板引用，以及确与任务相关的运行事实视图；保留来源、版本和观察时间 |
| context.memory | 有界的长期记忆选择及其来源；与本进程事实仓分开 |
| context.tools | 当前 Agent 获准的业务工具和角色控制能力；不包括事实仓刷新函数，不将本机命令清单直接作为授权 |
| context.config | 系统提示词快照、think/模型配置、工作意图、预算、输入/输出等边界、工作区及根/父关系、公共工作板绑定 |
| task_description | 用户任务或已接纳委托的原始描述、当前目标、范围、交付与验收要求；支持先保留原文，再按最小启动规则细化 |
| planner_enabled | 是否开放主动规划/重规划；独立于只规划或允许执行的工作意图 |
| id | Runtime 分配并登记的当前 Agent 标识；根任务与父 Agent 关系从绑定配置确定 |

前两篇的统一规格仍作为上述输入解析后的生效约定，避免维护两份可独立修改的 task、验收或 budget。`task_description` 中的验收要求可以尚未验证，调查材料可以尚未取得，但启动配置、权限和额度必须明确。

任务创建时先创建根任务与公共 Blackboard、登记主 Agent 和任务要求，再准备主 Agent 请求。初始只需要一个任务记录，未有详细计划或子 Agent 时也能保存目标、进度和待调查项。后续子 Agent 引用同一公共板及根预算。

`planner_enabled=false` 时仍然存在 Agent Loop、公共 Blackboard、进度同步和按角色允许的协作/委托。它只关闭主动规划能力，不能成为关闭全部 Runtime 管理工具的总开关。已有有效 Graph 可以按明确输入执行；没有有效图时不能在关闭规划的情况下偷偷生成计划再切 Graph。

`planner_enabled=true` 表示允许按需规划；简单任务可以一直使用 Loop。`/plan` 还具有独立的只规划工作意图，即使切 Graph 或委托调查也不得执行实际写入。

对子 Agent，规划许可只作用于自己的委托范围，不授予修改根计划或递归委托的权力。首版节点内部仍运行 Loop；需要改变整体依赖组织时由协调者提交根任务的计划/路由变化，不因统一输入而隐式新增嵌套 Graph 调度器。

## 7. 公共与临时 Blackboard

### 每个任务都有公共板

公共板在根任务创建时建立，覆盖单 Agent 和多 Agent、启用及关闭 planner 的所有任务。纯 Shell 对话不创建该板。

公共板提供统一读取入口，至少能看到：当前目标与验收、工作项及参与 Agent、进度与依赖、阻塞和待核实事项、证据与产物、共享决策，以及临时协作板目录。

任务、计划和依赖的权威记录仍由 Runtime 管理；公共板呈现其同版本投影或引用。模型通过受控提案修改状态，不能在普通板条目中写“完成”就改变任务状态，也不能维护第二套与调度器冲突的依赖关系。提交任务进度与公共板可见版本必须一致。

### 临时协作板登记

两个或多个 Agent 围绕特定问题需要共享材料时，可在同一根任务内创建临时协作板。公共板登记的元数据建议包括：板标识、目的、创建者、成员、关联任务/节点、读写范围、当前修订、状态和结果引用。

登记与创建在同一运行存储提交中完成；只有正文而没有目录项、或目录项指向不存在的板，都不能作为成功创建。参与者和工作项必须属于本根任务的有效记录，创建不得绕过委托或任务权限。

细化建议：参与成员可读写本板，协调者可查看以接纳交付；其他 Agent 可发现目录元数据，但读取正文和加入成员需通过 Runtime 检查。具体能力由已授权角色提供，不依赖开启 planner，也不通过普通文件/命令工具绕过。

### 协作、完成与恢复

临时板保存局部证据、假设、讨论结论与待处理事项；影响根任务的接口、依赖、结论或阻塞通过引用或摘要发布到公共板。正文不全量复制到公共板或所有 Agent 的上下文。

工作板记录与消息协议相互配合：写入一条记录不自动等同于创建请求、解除等待或完成节点；等待/答复必须绑定明确的请求或所需板修订，并进入现有的整体等待图检查。读取进度、轮询或反复创建工作板不能绕过预算及协作数量限制。

临时板按创建、使用、关闭/取消的生命周期管理。“临时”表示用途和成员范围有限，仍需随任务保存，以便暂停及重启后继续协作。关闭后停止写入并保留结果引用；相关验收或恢复仍依赖的记录不能立刻删除。父任务取消、参与者失效或计划替换时，结算相关等待并更新目录状态。

所有板共享根任务的总容量、记录数及协作限制，还需设单板/单次读写边界；关闭后重新创建不能无限重置累计限制。具体默认值和最终控制工具接口需要后续定稿。事实刷新函数始终不进入这些模型协作接口。

## 8. Loop 与 Graph 的切换

任务入口先进入能执行的模式；简单、探索性强、下一步依赖观察结果的工作可用 Loop。已有明确工作项和依赖时可以提交有效计划并进入 Graph；执行中发现依赖失效、缺少信息或需要重新调查时可以回到 Loop。

切换由模型或操作者提出，Runtime 校验后提交，必须满足：

- 已启动工具批次结算完毕，未知副作用先核实。
- 进入 Graph 时已有可执行且版本有效的任务图；需要规划但能力未开放时保持当前可用流程并报告原因。
- 根任务、Agent 标识、公共/临时 Blackboard、已接纳产物和预算保持连续。
- 不通过模式切换清除验收、依赖、只规划限制或协作等待。
- 使用已有切换/转换边界限制反复震荡；保留切换原因和未完成工作。

Blackboard 跟随同一任务，不在每次模式切换时重新创建。Graph 是任务组织方式，不是另开一份 Agent 总预算。

## 9. 与现有实现的差异和模块归属

| 方面 | 当前代码 | 本次目标 |
| --- | --- | --- |
| 普通 CLI 输入 | `Command::Input` 直接 start 并 execute 一个任务 | 默认会话回复，满足任务入口条件才进入 Runtime |
| 系统事实 | 环境配置解析和有限 debug 快照 | 完整事实域采集、进程内存仓及内部刷新能力 |
| Think 配置 | 主要在应用启动时按 vendor 配置 | Shell 可选择启用及强度，并与任务配置/续接明确衔接 |
| 规划开关 | 与运行时工具装配存在耦合 | planner 仅控制规划，公共板和其他管理能力独立存在 |
| Blackboard | 每个 RunState 有一个共享记录板 | 任务公共视图及临时协作板登记、权限和恢复 |
| `/resolver` | 尚无该命令 | 直接执行、按需规划；与 `/resolve` 分开 |

源码参考：[CLI 分派](../../agent-app/src/cli/dispatch.rs)、[应用环境](../../agent-app/src/config/environment.rs)、[Provider 装配](../../agent-app/src/provider.rs)、[提示词/工具装配](../../agent-core/src/agent/runtime/prompt/instructions.rs)、[Blackboard](../../agent-core/src/agent/blackboard/mod.rs)。

建议将平台事实采集、内存事实仓、Shell 输入路由、模式配置及对话展示放在 `agent-app` 的独立职责模块；核心接收显式的事实视图和生成配置，不自行读取应用环境。统一任务输入、Blackboard/临时板、预算、Loop/Graph 和检查点仍放在 `agent-core` 的既有领域及 runtime 分组中。vendor 负责协议和 think 参数适配，不负责判断任务、采集主机或管理工作板。

事实采集与内部刷新可以复用应用内的有界进程/读取支持，但不能因为复用启动机制就注册为模型工具。新增依赖、平台调用、生成配置 contract 和持久化格式在具体实现前评估；本稿不提前新增 crate。

## 10. 验收场景与待定项

| 场景 | 预期行为 |
| --- | --- |
| 首次启动 | 四个事实域都有成功结果或明确受限/失败状态，进入 Shell；没有无输入任务 |
| 创建多个 Agent | 共享事实仓，创建动作本身不重复采集本机 |
| 内部调用刷新 | 成功域更新、失败域保留旧观察时间；所有对外工具定义中均不存在刷新能力 |
| 普通闲聊或开启 think 的问答 | 使用精选上下文直接回复；无 Task、planner、任务 Blackboard 或实时事实注入 |
| 用户请求实际修改文件 | 模型产生任务分支，保存任务与公共板后才开始获准操作 |
| `/plan` | 进入任务并允许调查/分解；保持只规划限制 |
| `/resolver` | 进入执行；简单任务可用 Loop，复杂任务按需规划 |
| planner 关闭且无子 Agent | 公共板仍存在，能同步任务、进度和依赖状态 |
| 子 Agent 创建临时板 | 同步登记公共目录；成员/来源/任务绑定明确，重启后可恢复 |
| Loop/Graph 切换 | 同一根任务、工作板和预算延续，旧验证不会错误套用新输入 |
| 任务暂停后闲聊 | 不自动恢复或清零任务；明确继续时沿用原记录 |
| 路由响应中断或同轮重投 | 不执行半条控制结果，不重复创建任务 |

仍待确定：运行期事实刷新的触发时机（用户明确暂不定）；事实域的各平台实现与资源上限；Shell 入口判断的流式协议与错误回退；think 和模式的最终交互形式；临时板控制接口、权限细节、数量/容量与清理规则；会话与任务用量的最终展示口径。

这些细节不改变本次已明确的整体流程。实现时仍遵守根 AGENTS.md：本轮没有修改代码、运行构建、添加或执行自动化测试，也没有实际采集或输出本机环境变量/IP。
