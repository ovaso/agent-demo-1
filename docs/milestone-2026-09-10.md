# 阶段总结：缓存运行时与工具装配（2026-09-10）

前四节记录 `d35462a` 阶段的实现与验证；后续宏目录调整和测试删除见末节。此前的测试数量属于历史记录，当前项目已不保留这些测试。

本阶段完成缓存与 Token 消耗改造，并整合工具拆分、自动注册和调试模式。缓存部分已按功能形成独立提交（`b5a7101` 至 `98cf872`）；本次提交保存其余工具改动及本总结，作为下一轮实际使用验证的基线。

## 已完成的缓存改造

- 修正 DeepSeek 缓存读取用量解析，按输入 Token 加权计算命中率；记录响应模型和请求体大小，避免混淆请求命中次数与 Token 命中率。
- 每个 Agent 保存独立的运行状态快照和增量，追加动态信息；执行阶段去掉重复工具定义，限制节点结果预览，减少每轮前缀变化与重复输入。
- 保留模型续接数据和检查点语义；截断或未完成的模型响应先暂停，不执行其中的工具调用。
- 为记忆检索、完整模型请求、上下文窗口设置上限。按高低水位批量压缩，保留用户约束和完整工具交互，减少逐轮从历史队首删除造成的前缀变化。
- Token 预算在调用前持久化预留，按实际用量结算，主 Agent 与子 Agent 共享额度；恢复任务不重置消耗。新增输出上限及 CLI 额度调整，保留有限步数扩展与暂停恢复。
- 将缓存边界、输出参数和思考策略接入 provider 配置。DeepSeek 继续使用服务端自动缓存，Anthropic 按服务地址与配置决定缓存策略。

详细提交、固定场景和测量口径见[缓存运行时验证](benchmarks/cache-runtime-2026-09-10.md)；配置说明见[环境配置](environment.md)与[提示词缓存](prompt-caching.md)。

## 本次保存的工具改造

- `agent-app-tool` 承担七个普通业务工具及共享进程输出处理；`agent-tool-debug` 承担 `echo` 与 `debug_show_config`。应用入口只负责装配，环境解析和启动配置快照仍放在 `agent-app`。
- `#[tool]` 支持按组自动发现、应用状态注入和不同输出语义；宏选项、签名校验、代码生成分别拆分。通用注册与调用逻辑放在 `agent-core/src/tool`，避免在各工具中重复生成。
- 工具按固定的首次加入时间和名称排序，版本仅作本地参考；这些元数据不附加到模型工具 schema。旧检查点补齐元数据时保留原授权集合，并继续严格校验执行契约。
- 注册失败不留下部分工具；核心 `runtime_*` 的规划、调度、消息和权限执行仍由运行时负责。
- 调试组仅在 `--mode=debug` 时注册。`debug_show_config` 返回启动时解析的配置白名单，不输出 API key；`echo` 迁入调试组。旧任务若保存了 `echo` 授权，需要用 debug 模式恢复。
- 增加普通工具定义兼容快照、跨 crate 注册、上下文隔离、排序、元数据恢复、provider 序列化和 CLI 模式测试。用法与设计边界见[工具开发](tool-development.md)。

新增第三方依赖为关闭默认 features 的 `inventory 0.3.24`，用于跨模块和 crate 收集静态工具工厂。没有新增异步运行时，没有改变 SQLite 的部署方式或 release 编译配置。

## 已测结果与后续验证

缓存改造的固定 20 轮读取场景中，累计请求 JSON 从 3,379,419 降为 3,015,387 字节（减少 10.77%），同一 Agent 的完整消息前缀保留由 0/19 改为 18/19；剩余一次切换来自批量压缩。这是本地请求结构测量，不是服务端 Token 命中率。

同一场景峰值 RSS 从 15.36 MiB 增至 16.75 MiB，存在稳定历史窗口与续接状态的资源代价；本地耗时 0.42s 至 0.40s 的差异不足以承诺实际推理提速。该对照仅包含缓存改造，不包含工具重构。

下一步用官网的 `deepseek-flash` 数据验证实际效果，保持模型、任务输入和配置一致，分别观察首轮、普通续跑、压缩、恢复和子 Agent 调用。输入缓存命中率使用“缓存读取 Token / 全部输入 Token”，同时观察累计输入、输出和费用，不能只追求命中率。当前尚未完成真实服务的前后对照，也未测量工具重构的运行耗时变化。
